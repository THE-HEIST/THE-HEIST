📁 StudySmart/src/core/create/assignments.py

🔍 What does this file do?

This file handles adding new assignments to the system. It collects all the details from the user (name, module, deadline, difficulty), validates the input, calculates the priority score, and saves the assignment to the database. It includes robust input validation — empty fields are rejected, invalid dates are caught, and difficulty must be 1-5.

📖 Key Parts Explained

Input Collection with Validation (name and module)

Each field uses a while loop that keeps asking until a non-empty value is provided. This is a simple but effective way to ensure no field is left blank.

Pattern: Ask → Check if empty → If empty, show error and ask again

Date Validation (try/except — comes BEFORE difficulty)

datetime.strptime(deadline, "%Y-%m-%d") tries to parse the date string into a date object. If the format is wrong (e.g., "31-12-2024" instead of "2024-12-31"), it raises a ValueError. The try/except catches this and returns False immediately — the assignment is not created.

The variable dl is assigned but not used; it serves purely as a validation check. If parsing succeeds, the code breaks out of the loop and continues to difficulty.

Difficulty Validation (try/except + nested while loop)

The difficulty input is wrapped in try/except ValueError. If the user types "abc" instead of a number, Python would crash — the except catches this and returns False.

Inside the try, a nested while loop checks the range: difficulty must be between 1 and 5. If the user types 6 or 0, it prints an error with dashes for emphasis and asks again.

This is a two-layer validation: First check "is it a number?" (try/except), then check "is it in the right range?" (while loop).

Building the Assignment Dictionary

Creates a dictionary with all the fields, then calculates the priority score and level before saving. The assignment starts with "completed": False (not done yet).

Note: The source code contains a commented-out block that previously calculated days_remaining from the deadline. This was removed because the priority score is now calculated inside calculate_priority_score(), making the separate calculation unnecessary.

Return Values

→ return True — Success (assignment was added successfully)

→ return False — Bad input (invalid difficulty or date format)

These return values let the caller (tests) know if the operation succeeded or failed.
