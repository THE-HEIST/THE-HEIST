📁 Directory Structure

📄 config4test.py

📁 StudySmart/src/data_processing_module/config4test.py

🔍 What does this file do?

This file is almost identical to config.py, but it creates separate database instances for testing. When running tests, we don't want to accidentally modify the real user data or assignments. So this file points to test-specific JSON files in a data/test/ folder.

Analogy: If config.py is the real filing cabinet at the office, config4test.py is a practice filing cabinet in the training room — same structure, but separate data that can be safely messed with.

📝 Full Source Code

from src.LangaDB.controllers import LangaDB from pathlib import Path dir_path = Path(__file__).resolve().parent.parent.parent test_assignments = dir_path / 'src' / "data" / "test" / "assignments.json" test_users = dir_path / 'src' / "data" / "test" / "users.json" test_assignments_db = LangaDB(db_path=str(test_assignments), default_data={"assignments": []}) test_users_db = LangaDB(db_path=str(test_users), default_data={"users": []})

📖 Line-by-Line Explanation

Lines 1-2: Imports

Same imports as config.py — LangaDB for the database and Path for file paths.

Line 4: Finding the Project Root

dir_path = Path(__file__).resolve().parent.parent.parent

This goes up three levels from config4test.py (which is at src/data_processing_module/config4test.py):

→ .parent → src/data_processing_module/

→ .parent → src/

→ .parent → StudySmart/ (project root)

Note: This is different from config.py which only goes up two levels. The difference is because config4test.py constructs the path differently — it builds the full path from the project root instead of from a relative parent directory.

Lines 6-7: Test File Paths

test_assignments = dir_path / 'src' / "data" / "test" / "assignments.json" test_users = dir_path / 'src' / "data" / "test" / "users.json"

Constructs paths to the test data files. Instead of using src/data/assignments.json, it uses src/data/test/assignments.json. The / operator on Path objects joins path segments (it's overloaded — it normally means division).

Lines 9-10: Test Database Instances

test_assignments_db = LangaDB(db_path=str(test_assignments), default_data={"assignments": []}) test_users_db = LangaDB(db_path=str(test_users), default_data={"users": []})

Creates two LangaDB instances that point to the test data files. Tests import these test_assignments_db and test_users_db variables so they can add/remove test data without affecting real data.
