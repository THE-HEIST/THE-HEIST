🔍 Why does directory structure matter?

In programming, how you organize your files is just as important as the code itself. A well-organized project is easier to navigate, maintain, and collaborate on. StudySmart follows a standard Python project structure that separates source code, tests, configuration, and documentation into clear directories. Understanding this structure helps you know exactly where to find (or add) any piece of functionality.

🏗️ How the Directories Connect

📐 Architecture Flow

When you run python main.py, here's the chain of imports that happens:

main.py └── imports → src/LangaDB/controllers.py (database engine) └── imports → src/data_processing_module/config.py (initialize DB) └── creates → src/data/users.json (user data) └── creates → src/data/assignments.json (assignment data) └── imports → src/core/authentication/controllers.py (login system - NOT USED) └── imports → src/core/common/product.py (main menu) ├── imports → src/core/create/assignments.py (add new) ├── imports → src/core/read/assignments.py (view all) ├── imports → src/core/update/mark_as_done.py (mark done) ├── imports → src/core/delete/assignment.py (remove) └── imports → src/core/common/calculate_priority.py (scoring)

📂 Directory Explanations

📄 main.py — The Front Door

This is the entry point — the first file Python reads when you run the program. It imports the database engine and configuration, then calls the main menu. See main.py documentation.

🗄️ src/LangaDB/ — The Database Engine

LangaDB is a custom-built JSON database created by the team. Instead of using SQLite or MySQL, they wrote their own mini-database that reads and writes JSON files. This is impressive for a student project! The controllers.py file contains the LangaDB class with methods like save(), all(), find(), query(), add(), update(), delete(), sort_by(), and more. See LangaDB documentation.

⚙️ src/data_processing_module/ — Database Setup

Contains two files: config.py creates the real database instances for Users and Assignments, while config4test.py creates separate test databases. This separation ensures tests never corrupt real user data.

💾 src/data/ — Where Data Lives

Contains the actual JSON data files: users.json (registered users), assignments.json (all assignments), and session.txt (current logged-in user). The test/ subdirectory holds copies for testing. These files are automatically created when the program runs for the first time.

🧩 src/core/ — The Business Logic

This is where all the actual functionality lives, organized by CRUD operations:

•authentication/ — Handles user registration (SignUp), login (LogIn), and logout (LogOut). ⚠️ NOT USED in current version.

• common/ — Shared utilities: the priority scoring algorithm and the main menu loop that ties everything together.

• create/ — Adding new assignments with input validation.

• read/ — Viewing assignments, filtering by status, sorting by priority, and displaying completion statistics.

• update/ — Marking assignments as completed or undoing completion.

• delete/ — Removing assignments from the database.

🧪 tests/ — Quality Assurance

Contains unit tests that verify each feature works correctly. The test directory mirrors the source code structure: tests/create/ tests src/core/create/, tests/read/ tests src/core/read/, etc. Each test file uses monkeypatch to simulate user input and assert to verify results. Run all tests with pytest from the project root.

📋 instruction/ — Team Documentation

Contains learning materials and instructions for the development team. Includes guides for Git/GitHub workflows (in both English and Vietnamese) and LangaDB usage instructions. These are not part of the running program — they're reference docs for the developers.

🔄 .github/workflows/ — Automated Testing

Contains the GitHub Actions CI/CD pipeline configuration. Whenever code is pushed to GitHub, this workflow automatically runs all tests to catch bugs early. See CI/CD documentation.

🎯 Key Naming Conventions

📝 Python Naming Rules Used

• __init__.py — Every directory that Python should treat as a "package" needs this file. It can be empty (like most in this project) or contain initialization code.

• snake_case — All file names use lowercase with underscores: mark_as_done.py, calculate_priority.py. This is the standard Python convention.

• test_ prefix — All test files start with test_ so pytest can automatically discover them: test_assignment.py, test_delete.py.

• controllers.py — Files named "controllers" contain the main logic for their module (LangaDB engine, authentication (not used)).

• config.py / config4test.py — Configuration files. The 4test suffix indicates it's for testing only.

💡 Tip: The CRUD Pattern

Notice how src/core/ is organized into create/, read/, update/, and delete/ directories. This is the CRUD pattern — a fundamental concept in software engineering. CRUD stands for:

Create — Add new data (create/assignments.py)
Read — View existing data (read/assignments.py)
Update — Modify existing data (update/mark_as_done.py)
Destroy — Remove data (delete/assignment.py)

Almost every application that works with data follows this pattern!
