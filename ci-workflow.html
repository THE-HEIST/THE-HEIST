📄 CI/CD Workflow

📁 StudySmart/.github/workflows/continious_integration.yml

🔍 What does this file do?

This is a GitHub Actions workflow that automatically runs all tests every time someone pushes code to the main branch or opens a pull request. It tests across 5 different Python versions (3.9 through 3.13) to ensure the code works everywhere.

CI = Continuous Integration — automatically testing code changes.

📝 Full File Content

name: StudySmart CI on: push: branches: ['main'] pull_request: branches: ['main','Hùng-Anh','Quốc-Bảo','Trang-Anh','Bayane'] jobs: test: runs-on: ubuntu-latest strategy: matrix: python-version: ["3.9", "3.10", "3.11", "3.12", "3.13"] steps: - name: Checkout code uses: actions/checkout@v4 - name: Set up Python ${{ matrix.python-version }} uses: actions/setup-python@v5 with: python-version: ${{ matrix.python-version }} - name: Install dependencies run: | python -m pip install --upgrade pip pip install -r requirements.txt - name: Run tests run: | pytest

📖 Line-by-Line Explanation

name: StudySmart CI

A friendly name for the workflow that appears in the GitHub Actions dashboard.

on: (Triggers)

Defines when this workflow runs:

→ push to 'main' — Every time someone pushes code to the main branch

→ pull_request to branches — When someone opens a PR to main or any team member's branch (Hùng-Anh, Quốc-Bảo, Trang-Anh, Bayane)

strategy: matrix

Creates 5 parallel test runs — one for each Python version. If tests pass on Python 3.9 but fail on 3.13, the team knows there's a compatibility issue.

Steps Breakdown

1. Checkout code — Downloads the repository to the test server

2. Set up Python — Installs the specific Python version being tested

3. Install dependencies — Runs pip install -r requirements.txt

4. Run tests — Executes pytest to run all unit tests

If any step fails, the workflow stops and shows a red ❌ on GitHub.
